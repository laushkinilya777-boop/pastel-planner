# Личный пастельный планер: описание проекта

Дата: 22.11.2026
Статус: прошло проверку рецензентом, ждёт утверждения хозяйки

## 1. Зачем это

Личный планер, задачник и дневник для одного человека, хозяйки сайта. Вечером она садится за компьютер и расписывает следующий день: задачи с датой и временем. Днём отмечает выполненное, чаще всего с iPhone. Задачи, цели и важные даты должны храниться в одном месте, быть одинаковыми на телефоне и компьютере, а сроки можно переносить так, чтобы корректировки сохранялись. Сайт должен радовать глаз: пастельные светлые градиенты и картинки дня с котиками, собачками и мотивацией.

## 2. Цели

- Страница **«Сегодня»** открывается первой. На ней план на сегодня: задачи со временем, галочки и картинка дня.
- Страница **«Месяц»**: календарь месяца с планами, красными датами и дедлайнами. Нажатие на день открывает план этого дня, его можно смотреть и править.
- Страница **«Неделя»**: цели на неделю с полоской прогресса и задачи по дням недели.
- Страница **«Картинки»**: личная подборка. Картинки можно загрузить файлом, например сохранённые с Pinterest, или вставить прямой ссылкой на изображение.
- У задачи есть название, дата, необязательное время, необязательная заметка и необязательное напоминание.
- **Цели** бывают на неделю и на месяц, у каждой есть прогресс. **Прогресс растёт двумя путями (решение хозяйки):** к цели можно привязать задачи, и каждая выполненная задача добавляет +1, а ещё прогресс можно поправить вручную кнопками «+1 / −1». Итог = выполненные привязанные задачи + ручная поправка, из общей цели (например, 2 книги).
- **Красные даты и дедлайны** хозяйка добавляет сама. Автоматически праздники не подставляются. У даты есть переключатель **«каждый год»** для дней рождения и годовщин.
- **Повторяющиеся задачи (решение хозяйки: нужны).** Варианты повтора: каждый день; по выбранным дням недели (например, пн и ср); каждую неделю; каждый месяц в то же число; каждый год. Можно указать дату окончания повтора или оставить без конца.
- **Автоперенос:** невыполненная задача из прошлого дня сама переходит на сегодня с пометкой «↻ перенесено» и счётчиком переносов.
- **История изменений:** каждое изменение даты, времени или названия задачи записывается (когда, что было, что стало) и видно в карточке задачи.
- **Напоминания на iPhone и компьютере** приходят push-уведомлением незадолго до времени задачи, даже когда сайт закрыт.
- **Работает с телефона и компьютера**, данные синхронизируются. Сайт добавляется на экран «Домой» iPhone и открывается как приложение (PWA).
- **Доступ только у хозяйки:** вход по её почте, а база отдаёт данные только её аккаунту.
- **Стартовый набор из 12–15 картинок дня** (подробнее в разделе 6).

## 3. Не цели

- Сайт не многопользовательский: регистрации других людей нет, совместных списков нет.
- Нет автоматического импорта с Pinterest. Pinterest не даёт свободного доступа к картинкам, поэтому хозяйка добавляет их сама.
- Нет автоматических государственных праздников.
- Нет отдельного нативного приложения из App Store.

## 4. Анти-цели (провал, даже если «работает»)

- Чужой человек может увидеть задачи или картинки.
- Изменения, сделанные на телефоне, не видны на компьютере, или наоборот, либо данные теряются.
- Пользоваться неудобно на телефоне одной рукой: мелкие кнопки, горизонтальная прокрутка.
- Перенос срока затирает прошлую историю.
- Сайт выглядит как скучная офисная таблица, а не как светлый пастельный планер.

## 5. Ограничения

- Бесплатный хостинг: GitHub Pages. Публичный репозиторий означает, что код открыт, но данные закрыты входом. Ключи с правами администратора в код не попадают.
- Хранилище: Supabase на бесплатном тарифе (база Postgres, вход, файловое хранилище, Edge Functions, pg_cron). С компьютера хозяйки supabase.com и supabase.co открываются (проверено 22.11.2026). Доступ с iPhone через мобильный интернет проверяется на первом шаге сборки. Если не работает, работа останавливается и замена обсуждается с хозяйкой.
- Push на iPhone работает с iOS 16.4 и только когда сайт добавлен на экран «Домой». Разрешение запрашивается по нажатию кнопки.
- Интерфейс на русском языке.
- Каждый шаг сборки согласуется с хозяйкой (её прямая просьба).

## 6. Картинки дня: стартовый набор

Хозяйка попросила подобрать в интернете 12–15 картинок:
- белые котики с голубыми глазами;
- рыжие короткошёрстные котики;
- трёхцветные котики (коричневый, чёрный, светлый);
- смешные лабрадоры;
- чихуахуа;
- белые собачки мультипу;
- таксы;
- мотивационные картинки.

Решения (мои, их можно поправить):
- Фото животных берутся только с бесплатных сайтов с открытой лицензией (Unsplash, Pexels, Wikimedia Commons), чтобы не нарушать авторские права. Копии кладутся в хранилище Supabase, а не тянутся с чужого сайта, чтобы не пропадали.
- Перед добавлением хозяйке показывается галерея кандидатов, она выбирает, какие оставить.
- Мотивационные картинки сайт рисует сам: короткая фраза на пастельном градиенте. Стартовый набор фраз я пишу сама, хозяйка может добавлять свои. Так у фраз нет проблем с авторством, и они подходят по стилю.
- «Картинка дня» каждый день выбирается случайно из подборки и не меняется в течение дня. Можно нажать «другая».

## 7. Подходы

- **А. GitHub Pages + Supabase (выбран хозяйкой).** Синхронизация, вход, хранение картинок и push по расписанию на бесплатном тарифе. Минус: один раз нужна регистрация в Supabase.
- Б. GitHub Pages + Firebase. Push по расписанию требует платного тарифа с картой. Отклонён.
- В. Хранение только в браузере. Нет синхронизации между телефоном и компьютером, данные можно потерять. Отклонён.

## 8. Решения о том, как это строится (мои, не хозяйки)

- **Фронтенд:** обычные HTML, CSS и JavaScript (ES-модули) без сборщика, supabase-js подключается с CDN. Так сайт проще выкладывать и проще поддерживать.
- **PWA:** manifest, иконка, service worker. Service worker кэширует оболочку сайта и принимает push.
- **Вход:** по почте с одноразовым **6-значным кодом**, а не ссылкой. Ссылка на iPhone открылась бы в Safari, а не в приложении с экрана «Домой». Сессия хранится долго, чтобы не входить каждый день. Регистрация новых пользователей в Supabase отключается после создания аккаунта хозяйки.
- **Защита данных:** Row Level Security на всех таблицах и в хранилище, правило «строка принадлежит auth.uid()».
- **Данные** (примерный состав таблиц):
  - `tasks`: название, дата, время, заметка, выполнено (и когда), счётчик переносов, напоминание (за сколько минут, по умолчанию 15);
  - `task_history`: задача, когда изменено, поле, было, стало;
  - `goals`: период (неделя или месяц), начало периода, название, цель, текущий прогресс;
  - `special_dates`: дата, название, тип (красная дата или дедлайн), цвет;
  - `images`: путь в хранилище или внешняя ссылка, категория, подпись или фраза для мотивационных;
  - `push_subscriptions`: подписки устройств на уведомления;
  - `settings`: часовой пояс, тема (`theme`: opal / peach / mint) и прочие настройки.
- **История** пишется триггером в базе при изменении задачи, поэтому её нельзя «забыть» записать с фронтенда.
- **Автоперенос и напоминания** выполняются на сервере через pg_cron и Edge Function: перенос раз в сутки в 00:05 по часовому поясу хозяйки, проверка напоминаний раз в минуту, отправка Web Push с VAPID-ключами. Ещё при открытии сайта выполняется проверка «догнать перенос», если ночной запуск пропущен.
- **Часовой пояс** по умолчанию берётся с устройства при первом входе и сохраняется в настройках.
- **Дизайн:** светлые пастельные градиенты (персиковый, лавандовый, мятный, нежно-розовый, голубой), стеклянные карточки, линейные иконки (без эмодзи), шрифты Onest и Unbounded, крупные зоны нажатия, сначала мобильная вёрстка, на компьютере боковое меню. **Три светлые темы по настроению (решение хозяйки):** «Опал», «Персиковый закат», «Мятное утро»; выбор хранится в `settings.theme` и синхронизируется. Изюминки: кольцо выполнения дня вокруг даты и «жидкая» капсула прогресса цели с анимацией. Тёмная тема не делается.
- **Навигация:** на телефоне нижняя панель (Сегодня · Неделя · Месяц · Картинки), на компьютере боковое меню.

- **Работа без интернета (моё решение):** данные кэшируются на устройстве (IndexedDB). Отметки и правки без связи попадают в очередь и отправляются, когда связь вернётся. Если одно и то же поменяли на двух устройствах, побеждает последнее изменение. На экране видна маленькая пометка «не синхронизировано», пока очередь не пуста.
- **Напоминания по умолчанию (моё решение):** у задачи со временем напоминание за 15 минут включено сразу и выключается одним нажатием. У задачи без времени напоминания нет.
- **Автоперенос, детали (моё решение):** перенесённая задача сохраняет своё время, но повторно не напоминает (флаг «уже напомнено» не сбрасывается). Счётчик переносов растёт на +1 за каждый день переноса. Перенос записывается в историю.
- **Повторы, как устроены (моё решение):** правило повтора хранится в таблице `recurrences`, а сами дни заранее создаются обычными задачами в `tasks` на 60 дней вперёд (ежедневная задача cron досоздаёт новые). Поэтому галочки, история, напоминания и привязка к целям работают так же, как у обычных задач. При правке повторяющейся задачи сайт спрашивает: «только эта» или «эта и все следующие».
- **Повторы и автоперенос (моё решение):** повторяющиеся задачи **не переносятся** на завтра, иначе невыпитые витамины копились бы горкой. Пропущенный день остаётся в прошлом с пометкой «пропущено».
- **Ежегодные даты:** в `special_dates` есть флаг `yearly`, такие даты показываются в «Месяце» каждый год.
- **Привязка задач к целям:** в `tasks` есть необязательное `goal_id`, в `goals` есть `manual_adjust`.

## 10. Порядок работы (согласуется с хозяйкой на каждом шаге)

1. Вместе с хозяйкой создаём проект Supabase и проверяем доступ с телефона.
2. Таблицы, защита и вход.
3. Страница «Сегодня».
4. «Месяц» и «Неделя».
5. «Картинки» и стартовый набор.
6. PWA и напоминания.
7. Выкладка на GitHub Pages и установка на iPhone.
